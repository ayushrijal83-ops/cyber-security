**<span style="font-size: 24px">The challenge:</span>**<span style="font-size: 24px"> The password is in </span>`data.txt`<span style="font-size: 24px">, which is a </span>**<span style="font-size: 24px">hex dump</span>**<span style="font-size: 24px"> of a file that has been </span>**<span style="font-size: 24px">repeatedly compressed</span>**<span style="font-size: 24px"> multiple times with different tools.</span>

## <span style="font-size: 24px">The Full Solution — Step by Step</span>

### <span style="font-size: 24px">Step 1: Understand what we're dealing with</span>

`data.txt`<span style="font-size: 24px"> is a </span>**<span style="font-size: 24px">hex dump</span>**<span style="font-size: 24px"> — a text file containing hex characters that represent raw binary data. To work with the actual file, we first need to reverse the hex dump back into binary.</span>

---

### <span style="font-size: 24px">Step 2: Move to a writable directory</span>

<span style="font-size: 24px">The home directory is read-only, so we work in </span>`/tmp`<span style="font-size: 24px">:</span>

<span style="font-family: Menlo, Monaco, Consolas, Cascadia Mono, Ubuntu Mono, DejaVu Sans Mono, Liberation Mono, JetBrains Mono, Fira Code, Cousine, Roboto Mono, Courier New, Courier, sans-serif, system-ui; color: rgb(15, 17, 21); font-size: 24px">text</span>

```
cd /tmp
mkdir bandit12
cd bandit12
cp ~/data.txt .
```

<span style="font-size: 24px">Now we have our own copy of </span>`data.txt`<span style="font-size: 24px"> to work with.</span>

---

### <span style="font-size: 24px">Step 3: Reverse the hex dump</span>

<span style="font-size: 24px">Use </span>`xxd -r`<span style="font-size: 24px"> to convert hex text back into a binary file:</span>

<span style="font-family: Menlo, Monaco, Consolas, Cascadia Mono, Ubuntu Mono, DejaVu Sans Mono, Liberation Mono, JetBrains Mono, Fira Code, Cousine, Roboto Mono, Courier New, Courier, sans-serif, system-ui; color: rgb(15, 17, 21); font-size: 24px">text</span>

```
xxd -r data.txt > output
```

<span style="font-size: 24px">Now </span>`output`<span style="font-size: 24px"> is the actual binary file.</span>

---

### <span style="font-size: 24px">Step 4: Check the file type</span>

<span style="font-family: Menlo, Monaco, Consolas, Cascadia Mono, Ubuntu Mono, DejaVu Sans Mono, Liberation Mono, JetBrains Mono, Fira Code, Cousine, Roboto Mono, Courier New, Courier, sans-serif, system-ui; color: rgb(15, 17, 21); font-size: 24px">text</span>

```

```

<span style="font-size: 24px">Result: </span>`output: gzip compressed data`

<span style="font-size: 24px">The file has been compressed with </span>**<span style="font-size: 24px">gzip</span>**<span style="font-size: 24px">.</span>

---

1. **<span style="font-size: 24px">Check</span>**<span style="font-size: 24px"> the file type (</span>`file`<span style="font-size: 24px">)</span>

2. **<span style="font-size: 24px">Decompress/extract</span>**<span style="font-size: 24px"> with the right tool</span>

3. **<span style="font-size: 24px">Repeat</span>**<span style="font-size: 24px"> until you hit plain text</span>

<span style="font-size: 24px">No guessing. No shortcuts. Just methodical layer-by-layer peeling. This is exactly how real-world forensics and malware analysis work — you never know how many layers deep something is until you start.</span>
