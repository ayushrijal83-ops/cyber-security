## <span style="font-size: 24px">The Challenge</span>

<span style="font-size: 24px">The password for Level 20 is stored in </span>`/etc/bandit_pass/bandit20`<span style="font-size: 24px"> — but that file can only be read by the user </span>`bandit20`<span style="font-size: 24px">. I'm logged in as </span>`bandit19`<span style="font-size: 24px">.</span>

<span style="font-size: 24px">The home directory contains a </span>**<span style="font-size: 24px">setuid binary</span>**<span style="font-size: 24px"> called </span>`bandit20-do`<span style="font-size: 24px">. This binary lets me run commands as </span>`bandit20`<span style="font-size: 24px">.</span>

---

## <span style="font-size: 24px">What is a setuid binary?</span>

<span style="font-size: 24px">Normally, when you run a program, it runs with </span>**<span style="font-size: 24px">your</span>**<span style="font-size: 24px"> permissions. A setuid binary is different — it runs with the permissions of its </span>**<span style="font-size: 24px">owner</span>**<span style="font-size: 24px">, not the user who ran it.</span>

<span style="font-size: 24px">Think of it like a trusted delegate. The binary is owned by </span>`bandit20`<span style="font-size: 24px">, so when I run it, the program acts as </span>`bandit20`<span style="font-size: 24px"> — even though I'm </span>`bandit19`<span style="font-size: 24px">.</span>

---

## <span style="font-size: 24px">How to Spot a setuid Binary</span>

<span style="font-size: 24px">Run </span>`ls -la`<span style="font-size: 24px"> and look at the permissions:</span>

<span style="font-family: Menlo, Monaco, Consolas, Cascadia Mono, Ubuntu Mono, DejaVu Sans Mono, Liberation Mono, JetBrains Mono, Fira Code, Cousine, Roboto Mono, Courier New, Courier, sans-serif, system-ui; color: rgb(15, 17, 21); font-size: 24px">text</span>

```
-rwsr-x--- 1 bandit20 bandit19 14880 Jun 24 14:58 bandit20-do
```

## <span style="font-size: 24px">The Lesson</span>

<span style="font-size: 24px">Setuid binaries are powerful — and dangerous. They let users execute commands with elevated privileges. In real pentesting:</span>

- **<span style="font-size: 24px">Misconfigured setuid binaries</span>**<span style="font-size: 24px"> are a common privilege escalation vector</span>

- <span style="font-size: 24px">Always look for setuid binaries on compromised systems: </span>`find / -perm -4000 2>/dev/null`

- <span style="font-size: 24px">A setuid binary that runs arbitrary commands is essentially a backdoor</span>
