## <span style="font-size: 24px">What I Learned: SSH Private Keys</span>

<span style="font-size: 24px">Normally, SSH login uses a </span>**<span style="font-size: 24px">username + password</span>**<span style="font-size: 24px">. But there's another method: </span>**<span style="font-size: 24px">key-based authentication</span>**<span style="font-size: 24px">.</span>

- **<span style="font-size: 24px">Private key</span>**<span style="font-size: 24px"> = your secret. Keep it safe.</span>

- **<span style="font-size: 24px">Public key</span>**<span style="font-size: 24px"> = stored on the server.</span>

<span style="font-size: 24px">When you SSH with a private key, the server checks if it matches the public key. If yes → you're in. No password needed.</span>

<span style="font-size: 24px">Think of it like a physical key to a door. You don't say a password — the key itself opens the door.</span>

## <span style="font-size: 24px">The Problem I Hit</span>

<span style="font-size: 24px">I first tried to SSH from </span>**<span style="font-size: 24px">inside</span>**<span style="font-size: 24px"> the Bandit server:</span>

<span style="font-family: Menlo, Monaco, Consolas, Cascadia Mono, Ubuntu Mono, DejaVu Sans Mono, Liberation Mono, JetBrains Mono, Fira Code, Cousine, Roboto Mono, Courier New, Courier, sans-serif, system-ui; color: rgb(15, 17, 21); font-size: 24px">text</span>

```
ssh -i sshkey.private bandit14@localhost -p 2220
```

<span style="font-size: 24px">This failed because OverTheWire </span>**<span style="font-size: 24px">blocks SSH connections from </span>[<span style="font-size: 24px">localhost</span>](http://localhost)**<span style="font-size: 24px"> (connecting from the server back to itself).</span>

## <span style="font-size: 24px">The Solution</span>

3. **<span style="font-size: 24px">SSH</span>**<span style="font-size: 24px"> back in as </span>`bandit14`<span style="font-size: 24px"> using the key</span>

<span style="font-size: 24px">The </span>`-i`<span style="font-size: 24px"> flag tells SSH to use the private key instead of a password.</span>

## <span style="font-size: 24px">The Key Lessons</span>

1. **<span style="font-size: 24px">Private keys are powerful.</span>**<span style="font-size: 24px"> If you find one, you can often log in as that user without a password.</span>

2. [**<span style="font-size: 24px">localhost</span>**](http://localhost)**<span style="font-size: 24px"> ≠ external hostname.</span>**<span style="font-size: 24px"> Some servers block internal connections. The HINT said "log out" — meaning exit and reconnect from outside.</span>

3. **<span style="font-size: 24px">Windows vs Linux.</span>**<span style="font-size: 24px"> </span>`chmod`<span style="font-size: 24px"> doesn't exist on Windows PowerShell. If you're on Windows, either use WSL or fix permissions with </span>`icacls`<span style="font-size: 24px">.</span>

4. **<span style="font-size: 24px">Read the HINT file.</span>**<span style="font-size: 24px"> It literally told me the answer — "log out and log in again."</span>
